# Задание: полный цикл фаззинга на cronie

Цель: пройти полный цикл **выбор функции → обёртка → корпус → AFL → libFuzzer → покрытие**
на реальном проекте (cronie 1.5.7) руками. Время: 2–3 часа самостоятельной работы.

Всё выполняется в контейнере `fuzz-c`:

```
docker run -d --name fuzz-course --rm fuzz-c:latest sleep infinity
docker exec -it fuzz-course bash
```

Полезные пути внутри контейнера:

| Путь | Что |
|---|---|
| `/opt/fuzzenv/src/cronie-1.5.7/` | исходники cronie |
| `/opt/fuzzenv/refs/cronie/` | референс-обёртка `fuzz_load_entry.c` + `config.h.manual` + `cron-paths.h.manual` + корпус |
| `/opt/course/exercises/full-cycle/seed/` | стартовые сиды задания (шаг 5) |
| `/opt/course/exercises/full-cycle/solution/` | решение (смотрить только после завершения) |

Рабочая папка — любая своя (например `/root/task/`).
`fuzz_load_entry.c` — образец обёртки: читай его, но **свою обёртку пиши с нуля**.

## Шаг 1. Отчёт lizard (10 мин)

Прогони lizard по исходникам cronie и сохрани отчёт:

```
lizard /opt/fuzzenv/src/cronie-1.5.7/src/*.c > lizard-report.txt
```

Ответь письменно: какие 5 функций по CCN? Какие из них **не подходят** для фаззинга
и почему (приведи 2 конкретных причины по каждой)?

## Шаг 2. Выбор функции (10 мин)

Выбери функцию, которую будем фаззить. Критерии — курс, раздел 2
(вход-байты, минимум побочных эффектов, минимум зависимостей).
Обоснуй выбор в 3–5 предложениях.

> Подсказка: парсер `KEY=VALUE`-строк в `src/env.c` (чистый конечный автомат,
> файл уже линкуется вместе с `misc.c` и `pw_dup.c`).

## Шаг 3. Обёртка (40–60 мин)

Напиши `fuzz_<имя_функции>.c` по правилам курса §3:
- один файл на **оба** фаззера через `#ifdef __AFL_FUZZ_TESTCASE_BUF`;
- общая `do_fuzz(data, size)`;
- без накапливаемого глобального состояния между итерациями;
- в заголовочном комментарии: цель, функция, команды сборки.

По образцу референса подумай, как целевая функция получит данные:
`fmemopen`? dispatch-байт?

## Шаг 4. Сборка (20 мин)

Собери оба таргета (команды — курс, раздел 4):

- `fuzz_<f>_lf` — `clang -fsanitize=fuzzer,address -g -O1 ...`
- `fuzz_<f>_afl` — `afl-clang-fast -g -O1 ...`

Разовые приготовления (см. референс):

```
cp /opt/fuzzenv/refs/cronie/config.h.manual      /opt/fuzzenv/src/cronie-1.5.7/config.h
cp /opt/fuzzenv/refs/cronie/cron-paths.h.manual  /opt/fuzzenv/src/cronie-1.5.7/src/cron-paths.h
```

Если сборка падает — сначала посмотри таблицу ошибок (курс, раздел 4.3).

## Шаг 5. Стартовый корпус (10 мин)

В `/opt/course/exercises/full-cycle/seed/` лежат 3 валидных crontab-файла. Скопируй их себе
(`cp /opt/course/exercises/full-cycle/seed/*.cr corpus/`) и проверь каждый: `./fuzz_<f>_lf` на
одном файле не должен упасть.
Добавь **ещё 1–2 файла**, покрывающих ветви парсера, которые сиды не задевают
(подсказка: кавычки, пустые значения, экранирование). Обоснуй, зачем.

## Шаг 6. Запуск AFL (10 мин)

```
AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1 afl-fuzz -i corpus -o out -V 120 ./fuzz_<f>_afl
```

> Без переменной `AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1` `afl-fuzz` в
> контейнере не стартует вовсе (`PROGRAM ABORT: Pipe at the beginning of
> 'core_pattern'`) — подробности в курсе, раздел 6.1.1.

Пускай живёт 1–2 минуты (флаг `-V 120` остановит его самостоятельно) —
если хотите, Ctrl-C раньше. Сними копию экрана
и сохрани `out/default/fuzzer_stats`.

Ответь письменно: сколько exec/s? На сколько вырос корпус из стартовых N?
Сколько edges открыто из скольких? Что значит `stability`?

## Шаг 7. Запуск libFuzzer (10 мин)

```
./fuzz_<f>_lf corpus -max_len=4096 -runs=100000 -print_final_stats
```

Ответь письменно: что такое `cov` и `ft` в итоговой строке?
Почему libFuzzer напечатал recommended dictionary, а AFL — нет?
Чем отличается рост покрытия у AFL (edges) и у libFuzzer (cov/ft)?

## Шаг 8. Покрытие и выводы (10 мин)

Собери в `results.md` одно сравнение:

| | AFL | libFuzzer |
|---|---|---|
| exec (за прогон) | | |
| скорость exec/s | | |
| покрытие (edges / cov,ft) | | |
| финальный корпус | | |

и 3–5 предложений: что показал бы этот цикл дальше (куда копать:
словарь? конкретные ветви? другой таргет?).

## Критерии сдачи

- [ ] отчёт lizard + обоснование выбора функции;
- [ ] обёртка по правилам (один файл, два фаззера, без глобального состояния);
- [ ] обе сборки;
- [ ] корпус ≥5 файлов с обоснованием;
- [ ] прогоны обоих фаззеров + `fuzzer_stats`;
- [ ] `results.md` с таблицей покрытия и выводами.

## Подсказки (читать, только если застрял >30 мин)

1. **Линковка**: `load_env` нужна из `env.c`; вместе с ней линкуются
   `misc.c` (get_string/get_char) и `pw_dup.c`. Список — в референсе.
2. **Глобальные cronie**: `LineNumber`, `DebugFlags` и другие — см. раздел 4.3 курса
   (поиск по тексту референса: `MAIN_PROGRAM`).
3. **AFL-ветка**: после `__AFL_INIT()` нужен `__AFL_FUZZ_INIT()`
   (декларации ptr/len) — без него `__AFL_FUZZ_TESTCASE_BUF` не соберётся.
4. **fmemopen**: буфер `data` живёт до `fclose(f)` — не освобождай/не меняй его.
